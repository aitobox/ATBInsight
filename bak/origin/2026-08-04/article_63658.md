# uv 0.12.0

## Summary
The release of **uv 0.12.0** introduces notable breaking changes, most prominently regarding the default project structure generated by the `uv init` command. This update shifts `uv` toward a standard `src/`-layout packaging model, integrates the `uv_build` backend, and automatically sets up executable script entry points.

---

## What's New in `uv init`

The [`uv init`](https://docs.astral.sh/uv/concepts/projects/init/) command is the standard shortcut in `uv` for bootstrapping a new Python project. Version 0.12.0 brings significant refinements to the generated directory structure compared to the previous `0.11.x` releases.

### Key Changes
* **`src/` Layout:** Projects now default to a clean [`src/` layout](https://packaging.python.org/en/latest/discussions/src-layout-vs-flat-layout/) (e.g., `src/uv_init/__init__.py`), replacing the old behavior of dropping a `main.py` directly into the project root.
* **Build Backend:** The `pyproject.toml` file is now configured with the [`uv_build` backend](https://docs.astral.sh/uv/concepts/build-backend/) out of the box, handling wheels and `.tar.gz` distributions when running `uv build`.
* **Command Scripts:** A new `project.scripts` block is automatically added to `pyproject.toml`, defining a script alias (e.g., `uv-init = uv_init:main`) that can be effortlessly executed via `uv run uv-init`.
