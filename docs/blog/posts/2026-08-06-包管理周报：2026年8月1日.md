# 包管理周报：2026年8月1日

### 文章背景与核心概要
本期包管理周报汇总了各大包管理生态系统的最新动态与重大更新。在安全方面，npm 引入了发布时恶意软件扫描机制，GitHub Actions 增加了对未验证工作流的审核限制，Arch Linux 也暂停了无人维护 AUR 包的接管以应对供应链攻击。在工具发布方面，uv (0.12.x)、pip (26.2)、Docker (29.7) 和 Maven (4.0.0-rc-6) 等核心工具均推出了重要新版本。此外，社区还就维护者可持续性、SBOM 可靠性及 EuroPython 2026 包管理峰会进行了深入讨论。

## 📌 概要

本周包管理领域的重点集中在跨生态系统的关键安全更新上，包括 npm 新推出的发布时恶意软件扫描、GitHub Actions 对未验证工作流的拦截审核，以及 Arch Linux 在经历近期漏洞利用攻击后禁用了无人维护 AUR 软件包的接管。在工具方面，**uv (0.12.x)**、**pip (26.2)**、**Docker (29.7)** 和 **Maven (4.0.0-rc-6)** 发布了重大版本，同时关于维护者可持续性、SBOM 可靠性以及 EuroPython 2026 包管理峰会的讨论也十分热烈。

> This week in package management brings critical security updates across ecosystems, including npm's new publish-time malware scanning, GitHub Actions holding unproven workflows, and Arch Linux disabling orphaned AUR package adoption following recent exploit campaigns. On the tooling front, major releases rolled out for **uv (0.12.x)**, **pip (26.2)**, **Docker (29.7)**, and **Maven (4.0.0-rc-6)**, alongside prominent discussions on maintainer sustainability, SBOM reliability, and the EuroPython 2026 Packaging Summit.

## 🔒 安全动态

*   **npm 发布时扫描**：[npm 现在会在发布阶段对软件包进行扫描](https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata/)，在可供安装之前拦截或暂停触发启发式规则的上传。需要合法安全相关行为的软件包必须在 `package.json` 的 `contentPolicy` 字段以及根目录 `DISCLOSURE` 文件中声明，并通过 2FA 或可信发布（Trusted Publishing）进行发布。一旦声明，后续版本中不得移除这些字段。

> *   **npm Publish-Time Scans**: [npm now scans packages at publish time](https://github.blog/changelog/2026-07-28-npm-publish-time-malware-scanning-and-dual-use-metadata/) before they are available for installation, holding or blocking uploads that trigger heuristics. Packages requiring legitimate security-relevant behaviors must declare them via a `contentPolicy` field in `package.json` alongside a root `DISCLOSURE` file, published using 2FA or trusted publishing. Once declared, these fields cannot be removed in subsequent versions.

*   **GitHub Actions 安全**：GitHub Actions [现在会挂起被识别为潜在恶意的工作流运行](https://github.blog/changelog/2026-07-28-github-actions-holds-unproven-workflows-for-approval)，直至拥有写权限的已认证协同人员批准。该策略对 github.com 上的公共仓库自动生效，无需额外配置。

> *   **GitHub Actions Security**: GitHub Actions [now holds workflow runs identified as potentially malicious](https://github.blog/changelog/2026-07-28-github-actions-holds-unproven-workflows-for-approval) until an authenticated collaborator with write access approves them. This applies automatically and without configuration to public repositories on github.com.

*   **Arch Linux AUR 限制**：在攻击者劫持无人维护的软件包部署基于 Tor 的远程控制木马后（这是自 [6 月 alvr 接管事件](https://nesbitt.io/2026/06/13/this-week-in-package-management) 以来供应链攻击升级的延伸），Arch Linux [禁用了 AUR 上孤立软件包的接管](https://lists.archlinux.org/archives/list/aur-general@lists.archlinux.org/message/DRDEU3JUSC72CB265XHXPFA3DFSLXPBP/)。事实证明，7 月实施的账户创建限制仍不足以抵御攻击；[LWN 提供了更多背景信息](https://lwn.net/Articles/1086489/)。

> *   **Arch Linux AUR Restrictions**: Arch Linux has [disabled orphaned-package adoption on the AUR](https://lists.archlinux.org/archives/list/aur-general@lists.archlinux.org/message/DRDEU3JUSC72CB265XHXPFA3DFSLXPBP/) following attackers taking over unmaintained packages to deploy Tor-based remote-access trojans—an escalation of the supply-chain campaign that began with the [alvr takeover in June](https://nesbitt.io/2026/06/13/this-week-in-package-management). Account creation restrictions implemented in July proved insufficient; [LWN has further context](https://lwn.net/Articles/1086489/).

*   **[你拥有的不是供应链，而是供应链大杂烩](https://opensourcesecurity.io/2026/07-supply-soup/)**（Josh Bressers）：认为标准的“供应链”比喻并不恰当，因为单个依赖项的输入涵盖了 CI 运行器、开发者工作站和 Commit 访问向量，而现有的工具在很大程度上忽略了这些输入。

> *   **[You Don’t Have a Supply Chain, You Have a Supply Soup](https://opensourcesecurity.io/2026/07-supply-soup/)** (Josh Bressers) argues that the standard supply-chain metaphor fails because inputs to a single dependency encompass CI runners, developer workstations, and commit access vectors—inputs that current tooling largely overlooks.

## 📊 学术论文

*   **[无边即无裁决](https://arxiv.org/abs/2607.22140)**（Zięba-Kozarzewski）：对 78,000 个野生 SBOM 进行分析发现，52.9% 的 SBOM 声明了零依赖边，仅有 0.10% 利用 CycloneDX 组成来标记不完整的图。将无边 SBOM 视为退化数据后，KEV 检出召回率从 0.600 提升到了 0.950。

> *   **[No Edges, No Verdict](https://arxiv.org/abs/2607.22140)** (Zięba-Kozarzewski): Analyzes 78,000 wild SBOMs to find that 52.9% declare zero dependency edges, with only 0.10% utilizing CycloneDX compositions to flag incomplete graphs. Treating edgeless SBOMs as degenerate data boosted KEV-detection recall from 0.600 to 0.950.

*   **[拒绝万灵丹：验证 Python 软件包构建](https://arxiv.org/abs/2607.21888)**（Dietrich 等人）：使用 `macaron` 和 `oss-rebuild` 重新构建了 12,180 个热门 PyPI 版本。尽管仅有 15.4% 至 19.1% 的 Wheel 与已发布的产物字节相同，但他们的 `daleq4py` 工具为 60.2% 至 78.9% 的源码等效构建建立了语义等效性。

> *   **[No Snake Oil: Verifying Python Package Builds](https://arxiv.org/abs/2607.21888)** (Dietrich et al.): Rebuilt 12,180 popular PyPI releases using `macaron` and `oss-rebuild`. While only 15.4% to 19.1% of wheels emerged byte-identical to published artifacts, their `daleq4py` tool established semantic equivalence for 60.2% to 78.9% of source-equivalent builds.

> *   **Fedora PURL Integration**: Fedora 45 accepted the [Adopt PURL Metadata](https://fedoraproject.org/wiki/Changes/Adopt_PURL_Metadata) change, enabling RPMs built from language ecosystems to carry virtual provides like `purl(pkg:cargo/libc@0.2.186)` across nine ecosystems automatically.
