# 腾讯开源 DFly2：共享目标稀疏 KV Cache 的创新投机解码技术

> # Tencent Open-Sources DFly2: Speculative Decoding That Reuses the Target’s Sparse KV Cache

### 文章背景与核心概要
在大语言模型 (Large Language Model, LLM) 的实际部署与长文本推理中，传统的投机解码 (Speculative Decoding) 虽然能显著提升生成速度，但往往需要让辅助草稿模型 (Drafter) 独立维护一份庞大的键值缓存 (KV Cache)，导致长上下文和高并发场景下的显存开销居高不下。为了攻克这一瓶颈，Tencent 旗下混元 AI Infra 团队正式开源了全新块级并行投机解码框架 **DFly2**。该框架专门面向原生稀疏的大语言模型设计，革命性地直接复用目标模型的隐层 KV Cache 和稀疏索引结果，彻底甩掉了草稿模型的独立显存包袱，将草稿解码计算复杂度与上下文长度解耦。基准测试结果表明，DFly2 在 DeepSeek-V4.1-Flash、GLM-5.3-Flash 及 Tencent 自研的 Hy4 flash 等主流模型上均实现了更高的草稿接受率，并在长上下文智能体任务中实现了高达 81% 的服务吞吐量跃升，为超长文本模型的高性能低成本推理树立了全新标杆。

---

## 概述

> ## Summary

Tencent 正式[开源了 DFly2](https://x.com/TencentAI_News/status/2125968859450802415)。这是一款创新的块级并行投机解码草稿模型 (Drafter)，专为原生稀疏架构的大语言模型 (Large Language Model, LLM) 打造，完美支持 DeepSeek-V4.1-Flash、GLM-5.3-Flash 以及 Tencent 自研的 [Hy4 flash](https://huggingface.co/tencent/Hy4-flash) 等模型。DFly2 巧妙地摒弃了草稿模型独立的键值缓存 (KV Cache)，转而直接共享目标模型的隐层 KV Cache 与稀疏索引器筛选结果，大幅削减了显存开销，不仅能支持更高的并发请求，还在长文本以及智能体任务中实现了高达 **81% 的吞吐量提升**。

> Tencent has [open-sourced DFly2](https://x.com/TencentAI_News/status/2125968859450802415), an innovative block-parallel speculative decoding drafter designed specifically for natively sparse Large Language Models (LLMs) such as DeepSeek-V4.1-Flash, GLM-5.3-Flash, and Tencent's own [Hy4 flash](https://huggingface.co/tencent/Hy4-flash). By cleverly eliminating the need for a separate draft KV cache—instead sharing the target model's latent KV cache and sparse indexer picks—DFly2 drastically reduces memory overhead, enabling higher concurrency and up to an **81% throughput increase** on long-context and agentic tasks.

## 核心速览 (TL;DR)

> ## TL;DR

* **模型规模**：为 Hy4 flash 配套推出的草稿模型参数量为 0.85B (8.5 亿参数)，包含 5 个网络层。
* **硬件环境**：在线服务测试基于搭载 vLLM 的 NVIDIA H20 GPU 展开 (单实例采用 TP8 张量并行)；vLLM 官方推荐配置默认面向 8 张 H200。
* **整体性能**：在所有测试的目标模型以及通用基准测试中，相比相同训练配方的 DFlash 与 DSpark，DFly2 均取得了更高的草稿接受率。
* **最佳表现**：在用户级解码速度持平的前提下，DeepSeek-V4.1-Flash 在 64K 上下文的 SWE 代码基准测试中吞吐量提升高达 81%。
* **最小收益**：在 temperature 为 0 的常规任务下，DFly2 相比 DSpark 在 Hy4 flash 上的性能提升幅度最小，为 3.9%。

> * **Size:** 0.85B-parameter, 5-layer drafter shipped with Hy4 flash.
> * **Hardware:** Serving tests utilized NVIDIA H20 GPUs with vLLM (TP8 per instance); default vLLM recipes target 8x H200.
> * **Performance:** Higher draft acceptance rates compared to same-recipe DFlash and DSpark across all target models and general benchmarks.
> * **Best Results:** Up to 81% more throughput on DeepSeek-V4.1-Flash (SWE 64K) at matched per-user speed.
> * **Smallest Gains:** 3.9% improvement over DSpark on Hy4 flash general tasks at temperature 0.

## 什么是 DFly2？

> ## What is DFly2?

DFly2 是由 Tencent 混元 AI Infra 团队研发的块级并行投机解码草稿模型，相关成果详见学术论文[《DFly2: Turbocharging Long-Context Speculative Decoding by Sharing the Target’s Sparsity》](https://arxiv.org/abs/2611.34776)。

> DFly2 is a block-parallel speculative decoding drafter developed by Tencent’s Hunyuan AI Infra team, detailed in the research paper [‘DFly2: Turbocharging Long-Context Speculative Decoding by Sharing the Target’s Sparsity’](https://arxiv.org/abs/2611.34776).

标准的投机解码技术通过引入轻量级辅助模型 (草稿模型) 预先生成候选 Token，再由大体积的目标模型通过单次前向传播进行批量验证，在确保输出完全无损的前提下成倍加快生成速度。然而在长上下文应用场景中，这一方案的成本却急剧攀升：因为传统草稿模型不仅必须对整个前文字符串执行注意力计算，还必须单独开辟并维护一份专属于自己的 KV Cache。

> Standard speculative decoding utilizes a small auxiliary model (drafter) to propose tokens while the larger target model verifies them in a single pass, ensuring the output remains entirely lossless. However, in long-context scenarios, this approach becomes costly because traditional drafters must attend over the entire prefix and maintain their own separate KV cache.

## DFly2 的工作原理是什么？

> ## How Does DFly2 Work?

DFly2 将草稿模型的每一层与目标模型中的稀疏注意力层进行一对一直接配对，实现了两项核心关键组件的共享：

> DFly2 pairs each draft layer directly with a sparse attention layer in the target model, sharing two key components:

* **KV 共享 (KV Sharing)**：草稿层直接读取与其配对的目标模型层的隐层 KV Cache。
* **索引共享 (Index Sharing)**：草稿层仅对目标模型稀疏索引器已选定的位置执行注意力计算 (即 top-$k$ 稀疏 KV)。
* **权重初始化 (Initialization)**：每个草稿层均直接使用配对目标层的权重进行初始化。
* **隐藏状态注入 (Hidden Injection)**：目标模型最后一层的隐藏状态通过门控机制注入到草稿块中。
* **块内校正 (Intra-Block Correction)**：草稿模型在一个候选块内逐槽位重新读取共享的上下文信息。

> * **KV Sharing:** The draft layer reads the paired target layer’s latent KV cache directly.
> * **Index Sharing:** It attends exclusively to positions already selected by the target’s sparse indexer (top-$k$ sparse KV).
> * **Initialization:** Each draft layer is initialized using its paired target layer’s weights.
> * **Hidden Injection:** The target's last-layer hidden state is gated into the draft block.
> * **Intra-Block Correction:** The drafter rereads the shared context slot-by-slot within a block.

根据 [AngelSpec GitHub 开源主页](https://github.com/Tencent/AngelSpec)的介绍，每一个草稿 Token 最多仅关注约 2,000 个 Key 向量，这使得无论上下文长度如何延伸，草稿生成的计算成本都基本保持平稳。此外，DFly2 完全跳过了 Prefill 预填充阶段，这意味着从 Prefill 切换至 Decode 解码阶段时，仅仅需要额外传递一个最后一层的隐藏状态。

> According to the [AngelSpec GitHub page](https://github.com/Tencent/AngelSpec), each draft token attends to at most ~2K keys, keeping drafting costs roughly flat regardless of context length. Furthermore, DFly2 skips prefill entirely, meaning the prefill-to-decode transfer only adds a single last-layer hidden state.

## 显存开销对比分析：独立缓存 vs. 共享缓存

> ## Memory Cost Analysis: Separate vs. Shared Cache

常规的 3 层草稿模型缓存会在每个 Token 上带来显著的额外显存负担 (以 bf16 数据类型计算，数据源自论文表 2)：

> A conventional 3-layer drafter cache adds significant memory overhead per token (bf16, based on paper Table 2):

| 目标模型 (Target Model) | 目标模型 KV (Target KV) | 草稿缓存 (Drafter Cache) | 显存增加倍数 (Increase Factor) |
| :--- | :--- | :--- | :--- |
| **DeepSeek-V4.1-Flash** | 4.4 KiB | 3.4 KiB | 1.76x |
| **GLM-5.3-Flash** | 11.7 KiB | 3.0 KiB | 1.26x |
| **Hy4 flash** | 17.2 KiB | 3.4 KiB | 1.20x |

在 32K 上下文长度下，彻底省去草稿模型的专用缓存后，显存池能够容纳的**并发请求数量提升了 1.73 倍**。

> At a 32K context length, removing the drafter's dedicated cache allows the memory pool to accommodate **1.73x more concurrent requests**.

在常规工作负载下，DFly2 相比最强的基线模型取得了 3.9% 到 10.5% 的优势；而在长上下文和智能体工作负载 (最高达 128K) 下，这一优势进一步扩大到了 **10.0% 到 31.5%**。

> DFly2 demonstrates a 3.9% to 10.5% margin over the strongest baseline on general workloads, increasing to **10.0% to 31.5%** on long-context and agentic workloads (up to 128K).

## 如何部署 DFly2

> ## How to Deploy DFly2

DFly2 已经作为内置功能随 [tencent/Hy4-flash](https://huggingface.co/tencent/Hy4-flash) 原生发布 (这是一个总参数量约 220B、激活参数约 12B 的 MoE 混合专家模型，支持长达 1M 的上下文窗口)。

> DFly2 ships natively inside [tencent/Hy4-flash](https://huggingface.co/tencent/Hy4-flash) (a ~220B total, ~12B active MoE model with a 1M context window).

* **vLLM**：可通过镜像 `vllm/vllm-openai:hy4-flash` 并在投机推理方法中指定 `dfly` 进行部署 ([vLLM 配置配方](https://recipes.vllm.ai/tencent/Hy4-flash)中默认已开启)。
* **SGLang**：可通过镜像 `lmsysorg/sglang:hy4-flash` 直接调用 `DFLY` 投机算法。
* **自定义训练**：若想在自己的稀疏模型上训练 DFly2，可参考 [AngelSpec GitHub 仓库](https://github.com/Tencent/AngelSpec) (快速启动配置需要 1 台包含 8 张 GPU 的节点服务器：其中 4 张负责推理，4 张负责训练)。

> * **vLLM:** Serves models using the `dfly` speculative method via `vllm/vllm-openai:hy4-flash` (enabled by default in the [vLLM recipe](https://recipes.vllm.ai/tencent/Hy4-flash)).
> * **SGLang:** Utilizes the `DFLY` algorithm via `lmsysorg/sglang:hy4-flash`.
> * **Training:** To train DFly2 on custom sparse models, utilize the [AngelSpec GitHub repository](https://github.com/Tencent/AngelSpec) (quick-start configuration requires 1 node with 8 GPUs: 4 for inference, 4 for training).

## 核心要点总结

> ## Key Takeaways

* DFly2 通过直接复用目标模型的稀疏 KV Cache 与索引器筛选结果，彻底消除了草稿模型额外的键值显存开销。
* 在单用户生成速度相当的前提下，在 64K 上下文长度的 DeepSeek-V4.1-Flash 上实现了高达 **81% 的吞吐量提升**。
* 在长上下文与智能体任务的 Token 接受率上，比相同训练配方的 DSpark 高出 10.0% 至 31.5%。
* 随 Hy4 flash 提供了开箱即用的 vLLM 和 SGLang 运行支持，并可通过开源的 AngelSpec 开展自定义模型训练。

> * DFly2 eliminates extra draft KV memory by directly reusing the target model's sparse KV cache and indexer selections.
> * Achieves up to **81% higher throughput** on DeepSeek-V4.1-Flash at 64K context with matched per-user speed.
> * Outperforms same-recipe DSpark by 10.0% to 31.5% on long-context and agentic token acceptance.
> * Available out-of-the-box via Hy4 flash on vLLM and SGLang, with training supported through AngelSpec.
