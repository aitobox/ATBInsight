文章背景与核心概要

在隐私计算与安全外包计算领域，同态加密 (Homomorphic Encryption) 是一项允许在密文上直接进行数学计算而无需提前解密的前沿密码学技术，其中 CKKS 方案以对定点实数和复数近似计算的高效支持而备受瞩目。然而，密文之间的同态乘法会带来两大严峻挑战：定点缩放因子的平方级膨胀以及噪音误差项的急剧扩大，如果不加控制，仅需数次运算就会耗尽计算精度。为了解决这一问题，必须引入“重缩放” (Rescaling，在密码学中也称模数切换 Modulus Switching) 技术，在保证解密正确性的同时将密文缩放因子和噪音安全拉回正常区间。本文作为 CKKS 系列教程的核心篇章，不仅深入浅出地推导了重缩放的数学本质，给出了精简的 Python 实现，还为后续引入留数系统 (Residue Number System, RNS) 突破深层同态计算的模数预算限制打下了坚实基础。

执行摘要

Executive Summary

本文继续探讨 CKKS 同态加密方案 (CKKS Homomorphic Encryption Scheme) 系列教程，重点聚焦于其核心算子——重缩放 (Rescaling，亦称为模数切换 Modulus Switching)。虽然在此前的章节中，我们已经实现了同态乘法与重线性化 (Relinearization)，但密文乘法天然会将定点缩放因子平方膨胀至 \(\Delta^2\)，并引发噪音误差项的迅猛增长。而重缩放技术能够安全地对密文多项式和内部误差项进行同步等比缩减。此外，单模数预算的消耗瓶颈，也为我们在后续章节中全面转向留数系统 (Residue Number System, RNS) 以高效管理超大模数预算埋下了伏笔。

This article continues the tutorial series on the CKKS homomorphic encryption scheme, focusing on the critical operation of rescaling (also known as modulus switching). While previous steps introduced homomorphic multiplication and relinearization, multiplication inherently scales up the fixed-point scaling factor to \(\Delta^2\) and causes rapid error growth. Rescaling safely scales down both the ciphertext and the error term. Furthermore, this limitation motivates the upcoming transition to the Residue Number System (RNS) to efficiently manage large modulus budgets.

1. 引言与研究动机

1. Introduction and Motivation

在上一篇关于密钥切换与重线性化的文章中，我们成功在同态乘法之后将三元密文恢复为自然优雅的“二元组”结构。然而，密文乘法操作也同时引入了两个亟待解决的严重问题：

In the previous article on key switching and relinearization, we restored the natural "two-tuple" ciphertext structure after homomorphic multiplication. However, multiplication introduces two major problems:

  1. 缩放因子平方级膨胀 (Squared Scaling Factor)：由于 CKKS 方案底层采用定点数算法 (Fixed-Point Arithmetic)，两个缩放尺度为 \(\Delta\) 的明文相乘后，所得密文的编码缩放因子会剧增至平方项 \(\Delta^2\)；
  2. 误差增长急剧加速 (Accelerated Error Growth)：在多项式展开时误差项会相互交叉相乘，其中一个误差分量会与 \(\Delta \cdot e\) 成正比急剧膨胀。
  1. Squared Scaling Factor: Because CKKS uses fixed-point arithmetic, multiplying two plaintexts of scale \(\Delta\) results in a ciphertext encoded with a squared scaling factor of \(\Delta^2\).
  2. Accelerated Error Growth: Error terms multiply out, with one component growing proportionally to \(\Delta \cdot e\).

为了化解这两项挑战，我们引入了被称为重缩放 (Rescaling) (或称模数切换) 的关键技术。与此同时，本文也为下一期教程中实现 CKKS 的留数系统 (RNS) 架构奠定了坚实的基础。

To solve these challenges, we use a technique called rescaling (or modulus switching). This article also sets the stage for implementing the Residue Number System (RNS) form of CKKS in the next installment.

2. 重缩放的数学原理

2. Rescaling Mathematically

我们首先来看一段密文 \(c = (c_0, c_1)\)，它对缩放因子为 \(\Delta^2\) 的明文多项式 \(m(x)\) 进行了加密，并且在私钥多项式 \(s\) 以及小范数误差多项式 \(e\) 下满足如下同余解密等式：

We begin with a ciphertext \(c = (c_0, c_1)\) encrypting a plaintext polynomial \(m(x)\) with scaling factor \(\Delta^2\), satisfying:

\[c_0 + c_1 \cdot s = \Delta^2 m + e\]

其中 \(s\) 为私钥多项式，\(e\) 为具有极小范数的误差多项式。我们希望设计一套重缩放算法流程，生成一个全新的密文 \(c' = (c_0', c_1')\)，使其满足：

for a secret key polynomial \(s\) and a small-norm error polynomial \(e\). We want a rescaling procedure producing a new ciphertext \(c' = (c_0', c_1')\) such that:

\[c_0' + c_1' \cdot s = \Delta m + e'\]

为什么简单的直接除法会失效

Why Simple Division Fails

最直观朴素的想法，莫过于直接将密文中的各个多项式分量除以 \(\Delta\)：

The naive approach is to divide the ciphertext components directly by \(\Delta\):

\[(c_0, c_1) \mapsto \left(\frac{c_0}{\Delta}, \frac{c_1}{\Delta}\right)\]

然而在模 \(Q\) 的有限环运算中，\(\Delta\) 可能根本不存在逆元（例如当模数 \(Q\) 与 \(\Delta\) 拥有共同的质因子时）。更为致命的是，即便 \(\Delta\) 在模 \(Q\) 意义下存在乘法逆元 \(\Delta^{-1}\)，直接乘以 \(\Delta^{-1}\) 也会让噪音发生灾难性爆炸，变得无法容忍，如下面的 Python 代码片段所演示：

However, \(\Delta\) may not be invertible modulo \(Q\) (e.g., if \(Q\) shares a prime factor with \(\Delta\)). Even when invertible, multiplying by \(\Delta^{-1}\) makes the noise unacceptably large, as demonstrated by this Python snippet:

Q = 2**60 - 93
delta = 2**40
delta_inv = pow(delta, -1, Q)

def centered(x):
    x %= Q
    if x > Q / 2:
        return x - Q
    return x

for e in [1, -2, 3, 5, -7]:
    print(f"e = {e:3d},  delta^-1 * e mod Q = {centered(delta_inv * e):>20d}")

正确的破局思路：实数除法与模数切换

The Correct Approach

既然模逆元行不通，我们不妨换个视角，直接在实数域上审视这个除法问题。首先将取模等式在整数域中展开（消除模运算）：

Instead, we treat the division over real numbers. Lifting the modulo equation:

\[c_0 + c_1 s = \Delta^2 m + e + tQ\]

此时两边同时除以 \(\Delta\)，可以得到：

Dividing by \(\Delta\) gives:

\[\frac{c_0 + c_1 s}{\Delta} = \Delta m + \frac{e}{\Delta} + t\frac{Q}{\Delta}\]

如果我们约束模数 \(Q\) 能够被 \(\Delta\) 整除，即存在某个整数 \(Q'\) 满足 \(Q = \Delta \cdot Q'\)，那么我们可以将重缩放操作的候选方案定义为对系数分别进行四舍五入舍入并切换到新模数 \(Q'\)：

By requiring \(Q = \Delta \cdot Q'\) for some \(Q'\), we define our candidate rescaling procedure as:

\[\text{Rescale}(c_0, c_1) = \left(\text{round}\left(\frac{c_0}{\Delta}\right), \text{round}\left(\frac{c_1}{\Delta}\right)\right) \bmod Q'\]

对舍入误差进行深入分析后可以发现，重缩放后的新误差项变为了 \(\frac{e}{\Delta} + z_0 + z_1 s\)。其中原本庞大的误差 \(e\) 被除以了 \(\Delta\)，而舍入引入的新增噪音 (\(z_0, z_1\)) 与私钥 \(s\) 结合后，只带来完全处于可控、可接受范围内的微小误差增量。

Analyzing the rounding error reveals that the new error term becomes \(\frac{e}{\Delta} + z_0 + z_1 s\), where rounding noise (\(z_0, z_1\)) combined with the secret key \(s\) introduces controlled, manageable error growth.

3. 代码实现：重缩放的工程落地

3. Rescaling in Code

为了在工程中实现重缩放，我们需要精心挑选能够整除 \(Q\) 的缩放因子。我们首先从编写单元测试配置入手（对应代码详见该提交记录 (Commit)）：

To implement rescaling, we need a scaling factor that divides \(Q\) exactly. The implementation starts with setting up our test configurations (found in this commit):

# rescaling_test.py
def test_rescale():
    rescaled_encoding_params = EncodingParams(
        scale=2**20,
        poly_modulus_degree=8,
        # This prime is close to NTT_64_BIT_PRIME / 2**20
        coefficient_modulus=2199023255521,
    )
    squared_encoding_params = EncodingParams(
        scale=2**40,
        poly_modulus_degree=8,
        coefficient_modulus=NTT_64_BIT_PRIME,
    )

    message = np.array([1, 2, 3, 4], dtype=np.complex64)

    context = CKKSContext(rescaled_encoding_params)
    sq_context = CKKSContext(squared_encoding_params)
    sk = sq_context.generate_symmetric_private_key()
    pt = encode(message, squared_encoding_params, sq_context.ntt_params)
    ct = sq_context.encrypt_symmetric(pt, sk)

    ct_rescaled = rescale(
        ct,
        rescaled_encoding_params.coefficient_modulus,
        context.ntt_params,
    )

    decrypted_product = context.decrypt_symmetric(ct_rescaled, sk)
    decoded_product = decode(decrypted_product, rescaled_encoding_params)

    np.testing.assert_allclose(decoded_product, message, rtol=0, atol=0.1)

而核心的 rescale 重缩放函数则实现得非常干净利落，其本质就是对多项式系数执行等比缩放与四舍五入舍入：

The core rescale function is implemented cleanly via polynomial coefficient rounding:

# rescaling.py
import numpy as np

from ckks_types import Ciphertext
from polynomial import ModQPolynomial
from params import NTTParams


def rescale_poly(
    poly: ModQPolynomial, new_modulus: int, new_ntt_params: NTTParams
) -> ModQPolynomial:
    # Note this only works because the NTT_PRIME fits comfortably in a 64-bit float.
    rescale_factor = np.float64(poly.coefficient_modulus) / np.float64(new_modulus)
    new_coeffs = np.round(poly.coefficients / rescale_factor)
    return ModQPolynomial(
        coefficients=new_coeffs,
        coefficient_modulus=new_modulus,
        modulus_degree=poly.modulus_degree,
        ntt_params=new_ntt_params,
    )


def rescale(ct: Ciphertext, new_modulus: int, new_ntt_params: NTTParams) -> Ciphertext:
    d0 = rescale_poly(ct.data[0], new_modulus, new_ntt_params)
    d1 = rescale_poly(ct.data[1], new_modulus, new_ntt_params)
    return Ciphertext(data=(d0, d1))

4. 模数预算与通往留数系统 (RNS) 之路

4. Modulus Budget and the Road to RNS

每一次执行乘法和重缩放步骤，系数模数 \(Q\) 的位宽都会缩小一个因子 \(\Delta\)。举个例子，假设 \(\Delta\) 的精度为 10 位 (10 bits)，那么一个典型的 64 位模数 \(Q\) 最多仅允许进行大约 6 次连续乘法。

Each multiplication and rescaling step decreases our coefficient modulus \(Q\) by a factor of \(\Delta\). If \(\Delta\) is 10 bits, a 64-bit modulus only permits roughly 6 sequential multiplications.

为了支持深度更大的复杂同态计算电路，我们需要成倍扩充系数模数 \(Q\)（例如达到 800 位以上）。然而，直接采用任意精度大整数算法会带来严重的串行计算瓶颈，从而摧毁运算性能。为了完美解决这一矛盾，我们引入了留数系统 (Residue Number System, RNS)：

To support deep circuits, we need a larger \(Q\) (e.g., 800 bits). However, big integer arithmetic destroys performance due to serial bottlenecks. To fix this, we introduce the Residue Number System (RNS):

  • 模数质因数分解：将大模数 \(Q\) 分解为若干互不相同的机器字长质数连乘积：\(Q = \prod_i q_i\)；
  • 基于 Sunzi 中国剩余定理的留数表示：根据 Sunzi 中国剩余定理 (Chinese Remainder Theorem, CRT)，模 \(Q\) 下的任意大数都可以等价表示为一组模各个独立 \(q_i\) 的余数数组（在密码学工程中称为“肢”或分量 Limb）；
  • 多项式组织为二维张量：原本的多项式系数表示被转换为结构紧凑的二维数组（例如对应 13 个 Limb 肢分量时为 13x1024）；
  • 重缩放极简化为张量切片：重缩放操作从复杂的算术计算蜕变为极其轻量级的“舍弃一个 Limb 肢分量”张量切片操作。
  • \(Q\) is factored into distinct primes: \(Q = \prod_i q_i\).
  • By Sunzi’s Chinese Remainder Theorem, numbers modulo \(Q\) are represented by arrays of residues (limbs) modulo each \(q_i\).
  • A polynomial becomes a 2D array (e.g., 13x1024 for 13 limbs).
  • Rescaling simplifies to dropping a limb by slicing the tensor.

如此一来，原本抽象而昂贵的模数预算消耗，就自然转变成了直观明了的层级预算 (Level Budget)——只需跟踪记录当前密文中还剩余多少个可用的 RNS 肢分量即可。

Thus, our modulus budget transitions into a level budget tracking how many RNS limbs remain.
