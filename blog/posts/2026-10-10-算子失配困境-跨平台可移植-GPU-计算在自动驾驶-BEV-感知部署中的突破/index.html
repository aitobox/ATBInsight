算子失配困境：跨平台可移植 GPU 计算在自动驾驶 BEV 感知部署中的突破

The Operator Mismatch Problem: Deploying BEV Perception with Portable GPU Compute

arXiv:2610.11504 [cs.AI]
Subjects: Artificial Intelligence (cs.AI)
Authors: Rohit Verma, Anand V Bodas
Submitted: October 8, 2026
DOI: 10.48550/arXiv.2610.11504

文章背景与核心概要

在当今自动驾驶系统中，鸟瞰图 (Bird's-Eye-View, BEV) 感知模型已成为深度融合车载相机图像与激光雷达 (LiDAR) 点云以实现三维空间精准目标检测的核心支柱。然而，这类先进模型在工程落地时却遭遇了严峻的“算子失配 (Operator Mismatch)”困境——主流推理运行时虽能高效支持常规密集卷积，却难以表达 3D 稀疏卷积，也缺乏处理几何离散映射 (Scatter) 算子的计算语义，加之现有稀疏卷积库普遍深度绑定 CUDA 与 PyTorch，导致工业部署被长期锁死在单一厂商的硬件生态中。为了打破硬件垄断并解决部署断层，研究人员提出了全新的跨平台部署框架 BEVPIPE，通过将感知网络创新性地解耦为由引擎托管的密集计算子图，以及体素化器 (Voxelizer)、稀疏编码器 (Sparse Encoder) 和 BEV 投影器 (BEV Projector) 三大外部扩展算子，并依托统一的共享 GPU 显存空间进行零开销数据打通。实验表明，BEVPIPE 在几乎无精度损失的情况下 (保留了 98.5% 的参考 mAP) ，不仅达成了相比传统方案高达 19.5 倍的端到端推理加速，更成功验证了在异构 GPU 后端上的无缝跨平台可移植性，为多模态 BEV 感知系统的通用工业化部署开辟了全新路径。

内容总结

Summary

现代自动驾驶系统高度依赖鸟瞰图 (Bird's-Eye-View, BEV) 感知模型，通过融合车载相机与激光雷达 (LiDAR) 数据来实现高精度的 3D 目标检测。然而，这类模型的实际部署却面临着严峻的 算子失配 (Operator Mismatch) 困境：标准推理运行时能够流畅处理常规的密集卷积，却难以兼容模型所需的特定专用算子 (如密集卷积 vs. 稀疏 3D 卷积 vs. 几何离散映射 scatter 算子) 。更为棘手的是，当前主流的稀疏卷积库普遍严格限定于 CUDA 并深度绑定 PyTorch，导致感知算法的工业部署被牢牢锁定在单一硬件厂商的生态之中。

Modern autonomous driving systems rely on bird's-eye-view (BEV) perception models to fuse camera and LiDAR data for 3D object detection. However, deploying these models is hindered by an operator mismatch between standard inference runtimes and specialized operations (dense convolutions vs. sparse 3D convolutions vs. geometric scatter operations). Furthermore, existing sparse convolution libraries are strictly CUDA-only and PyTorch-coupled, locking deployments to single-vendor hardware.

为了化解这一难题，作者提出了 BEVPIPE 框架。该框架旨在利用高可移植性的 GPU 计算 API 来部署多模态 BEV 感知流水线，并能够与生产级推理运行时无缝集成。BEVPIPE 的核心思路是将感知模型清晰地划分为两大部分：

  1. 由推理运行时统一托管的密集计算子图；
  2. 三个通过共享 GPU 显存空间紧密连接的外部算子扩展组件——体素化器 (Voxelizer)、稀疏编码器 (Sparse Encoder) 与 BEV 投影器 (BEV Projector)。

To solve this, the authors introduce BEVPIPE, a framework designed to deploy multimodal BEV perception pipelines using portable GPU compute APIs while integrating seamlessly with production inference runtimes. BEVPIPE works by partitioning the perception model into: 1. Runtime-managed dense subgraphs, and 2. Three external operator extensions (voxelizer, sparse encoder, and BEV projector), connected via a shared GPU memory space.

核心成果： 相比传统部署方案，BEVPIPE 实现了 19.5 倍的端到端加速比，同时保留了基准模型 98.5% 的参考 mAP，成功验证了其在不同异构 GPU 计算后端上的出色可移植性。

Key Results: BEVPIPE achieves a 19.5× end-to-end speedup over conventional deployments while retaining 98.5% of reference mAP, successfully demonstrating portability across different GPU backends.

论文摘要

Abstract

现代自动驾驶系统广泛依赖鸟瞰图 (Bird's-Eye-View, BEV) 感知模型，通过深度融合车载相机与激光雷达 (LiDAR) 输入以实现三维空间内的精准目标检测。尽管这类模型具备极高的精度，但它们却根本无法直接借助标准的工业级推理运行时完成部署。其根源在于严峻的“算子失配 (Operator Mismatch)”难题——推理引擎虽能高效处理常规密集卷积，却完全无法表达 3D 稀疏卷积，更缺乏处理几何离散映射 (Scatter) 算子的计算语义与指令支持。而在当下的产业生态中，几乎所有主流的稀疏卷积库均仅支持 CUDA 且深度绑定 PyTorch 框架，从而将 BEV 感知模型的落地彻底锁死在单一厂商的计算硬件与专有执行框架之中。

Modern autonomous driving systems rely on bird's-eye-view (BEV) perception models that fuse camera and LiDAR inputs to detect objects in 3D space. These models are accurate, but they cannot be deployed through standard inference runtimes. The reason is an operator mismatch between dense convolutions (which runtimes handle well), sparse 3D convolutions (which runtimes cannot represent), and geometric scatter operations (which runtimes have no vocabulary for). Today, every sparse convolution library is CUDA-only and PyTorch-coupled, locking BEV deployment to a single vendor's hardware and a single execution framework.

针对上述痛点，本文提出了 BEVPIPE 框架——一个基于高可移植性 GPU 计算 API 构建、可与生产级推理运行时无缝结合的多模态 BEV 感知流水线部署方案。BEVPIPE 创新性地将整个感知网络解耦为两大板块：一部分是由推理引擎统一调度的密集计算子图；另一部分则是三大外部算子扩展模块 (体素化器 voxelizer、稀疏编码器 sparse encoder 以及 BEV 投影器 BEV projector) ，并通过统一的共享 GPU 显存空间进行零开销数据打通。在实际评测中，BEVPIPE 相比传统部署方案取得了高达 19.5 倍的端到端加速，同时保留了基准模型 98.5% 的参考 mAP 精度。更为重要的是，我们验证了 BEVPIPE 在多种不同 GPU 计算后端之间的无缝跨平台可移植性。

We present BEVPIPE, a framework for deploying multimodal BEV perception pipelines using portable GPU compute APIs and integrating them with production inference runtimes. BEVPIPE partitions the model into runtime-managed dense subgraphs and three external operator extensions (voxelizer, sparse encoder, BEV projector), connected through a shared GPU memory space. BEVPIPE achieves a 19.5x end-to-end speedup over conventional deployments while retaining 98.5% of reference mAP. We also showcase that BEVPIPE is portable across different GPU backends.
