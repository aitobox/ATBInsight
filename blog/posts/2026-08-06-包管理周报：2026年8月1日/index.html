包管理周报：2026年8月1日

文章背景与核心概要

本期包管理周报汇总了各大包管理生态系统的最新动态与重大更新。在安全方面，npm 引入了发布时恶意软件扫描机制，GitHub Actions 增加了对未验证工作流的审核限制，Arch Linux 也暂停了无人维护 AUR 包的接管以应对供应链攻击。在工具发布方面，uv (0.12.x)、pip (26.2)、Docker (29.7) 和 Maven (4.0.0-rc-6) 等核心工具均推出了重要新版本。此外，社区还就维护者可持续性、SBOM 可靠性及 EuroPython 2026 包管理峰会进行了深入讨论。

这是本周报的第 11 期，由 包管理器 OPML 订阅源集合 以及在 Mastodon 上发布或转发的最新动态整理而成。

Week eleven of the roundup, compiled from the package manager OPML feed collection and updates posted or boosted on Mastodon.

📌 概要

本周包管理领域的重点集中在跨生态系统的关键安全更新上，包括 npm 新推出的发布时恶意软件扫描、GitHub Actions 对未验证工作流的拦截审核，以及 Arch Linux 在经历近期漏洞利用攻击后禁用了无人维护 AUR 软件包的接管。在工具方面，uv (0.12.x)、pip (26.2)、Docker (29.7) 和 Maven (4.0.0-rc-6) 发布了重大版本，同时关于维护者可持续性、SBOM 可靠性以及 EuroPython 2026 包管理峰会的讨论也十分热烈。

This week in package management brings critical security updates across ecosystems, including npm's new publish-time malware scanning, GitHub Actions holding unproven workflows, and Arch Linux disabling orphaned AUR package adoption following recent exploit campaigns. On the tooling front, major releases rolled out for uv (0.12.x), pip (26.2), Docker (29.7), and Maven (4.0.0-rc-6), alongside prominent discussions on maintainer sustainability, SBOM reliability, and the EuroPython 2026 Packaging Summit.

🚀 发行版本

  • mise 2026.7.14–18：默认的 Shell 参数设置现在仅全局生效，防止未受信任的本地仓库配置在信任评估前影响命令执行。新增了实验性的任务输出缓存功能（在源、工具和环境未改变时恢复声明的输出并重放日志），以及实验性的 Monorepo 任务功能（可推断 Node 工作区依赖边并将 package.json 脚本导入为 node:<package>#<script> 任务）。
  • mise 2026.7.14–18: Default shell-argument settings are now global-only, preventing untrusted local repository configs from influencing command execution prior to trust evaluation. Adds experimental task output caching (restoring declared outputs and replaying logs when sources, tools, and environments are unchanged) and experimental monorepo tasks that infer Node workspace dependency edges and import package.json scripts as node:<package>#<script> tasks.
  • Verdaccio 6.9.0：要求最低运行环境为 Node.js 22，并引入了带有 exports 字段的 CJS+ESM 双构建模式（将 import { runServer } from 'verdaccio' 解析为真正的 ES 模块）。内置的 @verdaccio/config 更新至 js-yaml 4.3.0，修复了 GHSA-52cp-r559-cp3m。
  • Verdaccio 6.9.0: Requires Node.js 22 as a minimum runtime and introduces a dual CJS+ESM build with an exports field (resolving import { runServer } from 'verdaccio' to a true ES module). Bundled @verdaccio/config updates to js-yaml 4.3.0, addressing GHSA-52cp-r559-cp3m.
  • setup-uv v9.0.0：将 prune-cache 的默认值修改为 false，以减轻对 PyPI 基础设施的压力，这可能会提高 GitHub Actions 的缓存使用率（详见 #967）。
  • setup-uv v9.0.0: Flips the prune-cache default to false to reduce pressure on PyPI infrastructure, which may result in higher GitHub Actions cache usage (details in #967).
  • Renovate：
    • 43.282.0 配置 mise 管理器以 MISE_SAFE=1 模式运行 mise lock（上周已引入），消除了未受信任分支上对 allowedUnsafeExecutions 的需要。
    • 43.283.0 增加了 commitTrailers 选项。
    • 44.0.0 是因 Squash 合并 PR 中遗留的 BREAKING CHANGE 页脚而触发的意外大版本更新；44.x 被视为 43.x 的延续，实际不包含破坏性变更。
  • Renovate:
    • 43.282.0 configures the mise manager to run mise lock in MISE_SAFE=1 mode (introduced last week), eliminating the need for allowedUnsafeExecutions on untrusted branches.
    • 43.283.0 adds a commitTrailers option.

    • 0.12.0 包含多项正确性改进：uv init 默认采用带有 uv_build 的打包 src/ 布局，拒绝会覆盖解释器的 wheel 包，并强制执行 --require-hashes 指令（拒绝仅含 MD5 的哈希）。
    • 0.12.1 引入了通过 --prerelease-package 实现的单包预发布策略，接受本地 HTML 文件作为 Flat Index，并在预览版 uv check 中增加了 --fix 选项。
  • uv:
    • 0.11.33 runs malware checks against locked tools before pulling them from the cache, and updates preview lockfiles to support reading/writing without embedded package.metadata.
    • 0.12.0 collects correctness improvements: uv init defaults to a packaged src/ layout with uv_build, rejects wheels that would overwrite the interpreter, and enforces --require-hashes directives (refusing MD5-only hashes).
    • 0.12.1 introduces per-package pre-release policies via --prerelease-package, accepts local HTML files as flat indexes, and adds --fix to preview uv check.
  • pip 26.2：新增 --only-deps 选项以严格仅安装依赖，引入实验性 --use-feature=venv-isolation 标志以使用标准 venv 进行构建隔离而非 sitecustomize.py 覆盖，并基于 Cache-Control 响应头实现了简单索引（Simple Index）响应的本地缓存。旧版解析器（--use-deprecated=legacy-resolver）已被官方弃用，计划于 2027 年彻底移除。阅读 Richard Si 的版本发布文章。
  • pip 26.2: Adds --only-deps to install strictly a requirement’s dependencies, an experimental --use-feature=venv-isolation flag using a standard venv for build isolation instead of a sitecustomize.py overlay, and local caching of simple-index responses based on Cache-Control headers. The legacy resolver (--use-deprecated=legacy-resolver) is officially deprecated for removal in 2027. Read Richard Si's release write-up.

  • Maven 4.0.0-rc-6: Fixes RC-5 regressions, including globally-cached field-accessibility states breaking plugin configuration injection, a ConcurrentModificationException in the v4 API, and consumer POM conversion for BOM projects.

🔒 安全动态

  • npm 发布时扫描：npm 现在会在发布阶段对软件包进行扫描，在可供安装之前拦截或暂停触发启发式规则的上传。需要合法安全相关行为的软件包必须在 package.json 的 contentPolicy 字段以及根目录 DISCLOSURE 文件中声明，并通过 2FA 或可信发布（Trusted Publishing）进行发布。一旦声明，后续版本中不得移除这些字段。
  • npm Publish-Time Scans: npm now scans packages at publish time before they are available for installation, holding or blocking uploads that trigger heuristics. Packages requiring legitimate security-relevant behaviors must declare them via a contentPolicy field in package.json alongside a root DISCLOSURE file, published using 2FA or trusted publishing. Once declared, these fields cannot be removed in subsequent versions.
  • GitHub Actions 安全：GitHub Actions 现在会挂起被识别为潜在恶意的工作流运行，直至拥有写权限的已认证协同人员批准。该策略对 github.com 上的公共仓库自动生效，无需额外配置。
  • GitHub Actions Security: GitHub Actions now holds workflow runs identified as potentially malicious until an authenticated collaborator with write access approves them. This applies automatically and without configuration to public repositories on github.com.
  • Arch Linux AUR 限制：在攻击者劫持无人维护的软件包部署基于 Tor 的远程控制木马后（这是自 6 月 alvr 接管事件 以来供应链攻击升级的延伸），Arch Linux 禁用了 AUR 上孤立软件包的接管。事实证明，7 月实施的账户创建限制仍不足以抵御攻击；LWN 提供了更多背景信息。
  • Arch Linux AUR Restrictions: Arch Linux has disabled orphaned-package adoption on the AUR following attackers taking over unmaintained packages to deploy Tor-based remote-access trojans—an escalation of the supply-chain campaign that began with the alvr takeover in June. Account creation restrictions implemented in July proved insufficient; LWN has further context.

📝 推荐文章

  • 开源必须充满乐趣，否则终将消亡（Mike McQuaid）：探讨了维护者的乐趣作为支撑开源项目发展的根本稀缺资源，并以 Homebrew 的运营数据为例，指出由于自动化处理了繁琐的审核工作，去年 29 名维护者中有 26 名依然保持活跃。
  • Open Source Must Be Fun or It Will Die (Mike McQuaid) explores maintainer enjoyment as the fundamental scarce resource sustaining open source projects, highlighting Homebrew’s operational statistics where 26 of last year's 29 maintainers remain active thanks to automation handling tedious reviews.
  • 无处不在的包管理器（Patrick Linnane）：按平台分析了 Homebrew 的公开分析数据：约四分之一的事件发生在 Linux 上，其中默认搭载 brew 的 Universal Blue 镜像占非 CI Linux 流量的 26%，WSL 占 3.7%。
  • The Package Manager for Everywhere (Patrick Linnane) analyzes Homebrew's public analytics by platform: roughly a quarter of events occur on Linux, with Universal Blue images (shipping brew by default) accounting for 26% of non-CI Linux traffic, and WSL at 3.7%.
  • 你拥有的不是供应链，而是供应链大杂烩（Josh Bressers）：认为标准的“供应链”比喻并不恰当，因为单个依赖项的输入涵盖了 CI 运行器、开发者工作站和 Commit 访问向量，而现有的工具在很大程度上忽略了这些输入。
  • You Don’t Have a Supply Chain, You Have a Supply Soup (Josh Bressers) argues that the standard supply-chain metaphor fails because inputs to a single dependency encompass CI runners, developer workstations, and commit access vectors—inputs that current tooling largely overlooks.

📊 学术论文

  • 无边即无裁决（Zięba-Kozarzewski）：对 78,000 个野生 SBOM 进行分析发现，52.9% 的 SBOM 声明了零依赖边，仅有 0.10% 利用 CycloneDX 组成来标记不完整的图。将无边 SBOM 视为退化数据后，KEV 检出召回率从 0.600 提升到了 0.950。
  • No Edges, No Verdict (Zięba-Kozarzewski): Analyzes 78,000 wild SBOMs to find that 52.9% declare zero dependency edges, with only 0.10% utilizing CycloneDX compositions to flag incomplete graphs. Treating edgeless SBOMs as degenerate data boosted KEV-detection recall from 0.600 to 0.950.
  • 拒绝万灵丹：验证 Python 软件包构建（Dietrich 等人）：使用 macaron 和 oss-rebuild 重新构建了 12,180 个热门 PyPI 版本。尽管仅有 15.4% 至 19.1% 的 Wheel 与已发布的产物字节相同，但他们的 daleq4py 工具为 60.2% 至 78.9% 的源码等效构建建立了语义等效性。
  • No Snake Oil: Verifying Python Package Builds (Dietrich et al.): Rebuilt 12,180 popular PyPI releases using macaron and oss-rebuild. While only 15.4% to 19.1% of wheels emerged byte-identical to published artifacts, their daleq4py tool established semantic equivalence for 60.2% to 78.9% of source-equivalent builds.

🌐 行业资讯

  • EuroPython 2026：EuroPython 2026 包管理峰会笔记 已在上周的报道后上线。讨论集中在 Wheel 变体提供商信任（PEPs 817/825）、PyPI 应用 Lockfile 分发、通过 PURL 提供外部构建依赖元数据（PEPs 725/804），以及包管理理事会选举时间表。
  • EuroPython 2026: The EuroPython 2026 Packaging Summit notes are live following last week's coverage. Discussions centered on wheel-variant provider trust (PEPs 817/825), PyPI application lockfile distribution, external build-dependency metadata via PURL (PEPs 725/804), and Packaging Council election timelines.
  • WASM 目录：大多数 WASI Phase 2 提案现在均包含在 wasm.directory 上索引的已发布 OCI 软件包，这是一个拟在未来捐赠给 Bytecode Alliance 的 WebAssembly 组件元注册表。
  • WASM Directory: Most WASI phase 2 proposals now feature published OCI packages indexed on wasm.directory, a meta-registry for WebAssembly components slated for future donation to the Bytecode Alliance.
  • Composer 赞助计划：Composer 和 Packagist.org 跨三个年度级别启动了正式的赞助计划，以资助运营、安全和透明度日志，获得了 10 家创始企业赞助商和通过 PHP 基金会提供的 Sovereign Tech Agency 资金支持。
  • Composer Sponsorship: Composer and Packagist.org have launched a formal sponsorship program across three annual tiers to fund operations, security, and transparency logs, backed by ten founding corporate sponsors and Sovereign Tech Agency funds via the PHP Foundation.
  • Renovate 配置调试器：维护者 Sebastian Poxhofer 发布了 Renovate Config Debugger，允许用户通过编译后的 Renovate 代码在浏览器中直接分步执行解析、迁移、验证和预设匹配。
  • Renovate Config Debugger: Maintainer Sebastian Poxhofer released the Renovate Config Debugger, allowing users to step through parsing, migration, validation, and preset matching directly in the browser via compiled Renovate code.
  • GitHub Actions 同仓库 Actions 引用：Actions 工作流现在可以使用 uses: $/path/to/action 语法引用同一仓库中的 Actions，无需 actions/checkout 步骤即可干净利落地解析。
  • GitHub Actions Same-Repo Actions: Actions workflows can now reference actions in the same repository using uses: $/path/to/action, resolving cleanly without requiring a actions/checkout step.
  • Fedora PURL 集成：Fedora 45 采纳了 采用 PURL 元数据 的变更，使从语言生态系统构建的 RPM 能够自动跨 9 个生态系统提供像 purl(pkg:cargo/libc@0.2.186) 这样的虚拟 provides。
  • Fedora PURL Integration: Fedora 45 accepted the Adopt PURL Metadata change, enabling RPMs built from language ecosystems to carry virtual provides like purl(pkg:cargo/libc@0.2.186) across nine ecosystems automatically.
