导数对偶翻转：从正则导数到多项式自动微分的新视角

Derivative Flipping

文章背景与核心概要

在现代科学计算与深度学习中，高阶导数 (例如拉普拉斯算子或黑塞矩阵) 的求解往往面临着巨大的计算复杂度与内存开销。本文提出了一种令人耳目一新的全新思维范式：借鉴理论计算机科学中处理正则表达式的经典 Brzozowski 导数，在多元多项式空间构建起一种对称微分配对。通过将“微分算子”与“被求导表达式”的对偶身份巧妙翻转，让原本复杂的运算图作为算子去作用在极其简洁的目标多项式上，中间可能出现的状态被奇迹般地锁定在极小维度的固定基底空间内。这一优雅的洞见不仅为 Microsoft 开源的高性能库 folx 以及前沿的泰勒模式折叠自动微分算法提供了坚实直观的代数解释，更为我们设计下一代轻量级自动微分框架开辟了全新的数学视野。

内容概要

Summary

本文探讨了一种受正则表达式领域 Brzozowski 导数 启发而来的自动微分 (Automatic Differentiation, AD) 新视角。通过在多元多项式之间定义一种对称配对 \(\langle p, q \rangle\) ——即令其中一个多项式作为微分算子作用于另一个多项式并在零点处求值——我们可以将“微分算子”与“被求导表达式”进行令人惊叹的角色“翻转” (\(\langle p, q \rangle = \langle q, p \rangle\)) 。将一个复杂的表达式作为微分算子作用于一个简单的算子多项式 (比如拉普拉斯算子 \(x^2 + y^2\)) 时，求导过程中产生的所有中间表达式的复杂度会被严格限制在一个极小的固定基底空间内。这为诸如泰勒模式折叠 (Taylor-mode collapsing) 和 folx 等高效自动微分算法提供了一种极其直观的代数理论基石。

This post explores an alternative perspective on automatic differentiation (AD) inspired by Brzozowski derivatives for regular expressions. By defining a symmetric pairing \(\langle p, q \rangle\) between multivariate polynomials—where one polynomial acts as a differential operator on the other before evaluating at zero—we can "flip" the differentiator and the differentiated expression (\(\langle p, q \rangle = \langle q, p \rangle\)). Applying a complex expression as a differential operator to a simple operator polynomial (such as the Laplacian \(x^2 + y^2\)) bounds the space of intermediate expressions to a small, fixed basis, providing an intuitive foundation for efficient AD algorithms like Taylor-mode collapsing and folx.

我想带领大家换个角度来重新审视自动微分。在这篇文章中，我并不打算直接给出一个可以直接投入生产的完整自动微分算法，但它将揭示某些高级自动微分算法的实现机理——并有望为理解近年来学界发表的一些相关论文提供更直观、更通透的思维模型。

I want to take a look at another way of thinking about automatic differentiation. I'm not going to give an actual AD algorithm, but this will show how to implement some AD algorithms—and possibly provide an easier way to think about some published work.

背景知识：Brzozowski 导数

Background: Brzozowski Derivatives

首先，我想聊聊利用 Brzozowski 导数进行正则表达式匹配的原理。如果你对这块已经很熟悉，或者只想看核心微积分，完全可以跳过这一节；不过，这正是我在编写下文 Haskell 代码时脑海中涌现的灵感源泉。

First, I want to talk about regular expression matching using the Brzozowski derivative. You can skip this bit, though it's what I was thinking about as I wrote the code below.

我们先定义一个尖括号配对算子 \(\langle\cdot,\cdot\rangle\) ：如果正则表达式 \(R\) 能够匹配字符串 \(S\) ，则 \(\langle R,S\rangle=1\) ；若不能匹配，则为 \(0\) 。我从 Wikipedia 摘录了 Brzozowski 导数的定义，并对记号做了微调：

Let's define the angle bracket operator \(\langle\cdot,\cdot\rangle\) by \(\langle R,S\rangle=1\) if \(R\) is a regular expression matching the string \(S\), and \(0\) if it doesn't match. I'll copy the definition from Wikipedia, modifying the notation slightly:

\[ \begin{aligned} \partial_a a &= 1 \\ \partial_a b &= 0 \qquad \text{for each symbol } b \ne a \\ \partial_a \varepsilon &= 0 \\ \partial_a \varnothing &= 0 \\ \partial_a (R^*) &= (\partial_a R)R^* \\ \partial_a (RS) &= (\partial_a R)S \lor \nu(R)\partial_a S \\ \partial_a (R \lor S) &= (\partial_a R) \lor (\partial_a S) \end{aligned} \]

在 Wikipedia 上还附带有一些辅助定义 (例如判空函数 \(\nu(R)\) 等) 。

(along with some auxiliary definitions on Wikipedia).

如果你以前从没接触过这一概念，上面的公式看起来可能有点让人望而生畏，但其精髓其实全部凝聚在一条极其核心的性质之中：

If you've not seen it before, that definition looks scary, but it all comes down to one key property:

\[ \langle R,aS\rangle = \langle \partial_a R,S\rangle \]

你看，要想知道某个正则表达式是否能匹配字符串 \(S\) ，我们只需将字符串开头的字符一个个剥离下来，并把对应的导数算子依次作用在正则表达式 \(R\) 上即可。在此过程中，我们还需要在正则代数体系中进行化简消零。如果在处理完所有字符后，最终剩下的正则表达式能够匹配空字符串，那就意味着初始的正则表达式成功匹配了原字符串！关于如何将其工程化并高效落地的更多细节，可以参阅 Scott Owens 、 John Reppy 与 Aaron Turon 合著的经典论文 Regular-expression derivatives reexamined 。

So, to find out if a regular expression matches a string \(S\), we can peel off the letters from the front of it one by one and apply the corresponding derivative operator to \(R\). We also need to perform algebraic simplifications in the regexp algebra. If we end up with a regular expression that matches the empty string, then the original regexp matched the original string. For more details on making this practical, see Regular-expression derivatives reexamined by Scott Owens, John Reppy, and Aaron Turon.

虽然直觉上我们会担心：随着导数一层层求下去，中间生成的表达式会不会无限膨胀失控？但令人惊奇的是，在化简等价性 (即两个正则表达式匹配完全相同的字符串集合) 后，我们实际能得到的本质不同的独立表达式数量是严格有限的！这些有限的表达式，正好构成了用于识别目标正则语言的有限状态自动机 (Finite State Automaton, FSA) 的各个状态。

Although we might expect to get all manner of intermediate expressions when we keep differentiating, there is only a finite number of truly distinct expressions we can obtain (considering two regexps equivalent if they match identical sets of strings). They form the states of a finite state automaton for recognizing the regexp's target.

微积分中的微分配对

Differential Pairing in Calculus

现在，让我们把这种绝妙的思想平移到普通微积分中。给定一对多元多项式 \(p\) 与 \(q\) ，我们定义如下的微分配对：

Let's mimic that for ordinary calculus. Given a pair of multivariate polynomials \(p\) and \(q\), define:

\[ \langle p,q\rangle = \left. p(\partial_1, \partial_2, \ldots)\,q(x_1, x_2, \ldots) \right|_{x_1=x_2=\cdots=0} \]

我们可以直接在 Haskell 中将这一机制完整实现出来。最终，我将定义一个函数 pair p q ，专门用于计算上述尖括号所表示的配对值。

We can go ahead and implement this in Haskell. Ultimately, I'll define pair p q, which computes the pairing defined by the angle brackets.

Haskell 代码实现

Haskell Implementation

首先，我们在数域 a 上由变量元素 v 生成的环中定义表达式的数据结构：

First, I'll define expressions in a ring generated by elements of v over a:

data Expr v a = Var v
              | Expr v a :+: Expr v a
              | Expr v a :*: Expr v a
              | Lit a
              deriving (Eq, Show)

接下来，我们为该表达式类型实现 Num 数值接口，使其支持自然的算术运算：

Now we can give it the Num interface:

instance Num a => Num (Expr v a) where
  fromInteger = Lit . fromInteger
  (+) = (:+:)
  (*) = (:*:)
  negate x = Lit (negate 1) * x
  signum = undefined
  abs = undefined

理论上我还应该加入代数化简逻辑，不过作为纯粹用于教学演示的概念验证代码，倒也无需过度复杂化。紧接着，我们实现将 p 解释为作用于 q 上的微分算子的核心规则：

I should add simplification, though there's no real need when this code is purely pedagogical. Next, we implement the rules that interpret p as a differential operator acting on q:

apply :: (Eq v, Num a) => Expr v a -> Expr v a -> Expr v a

下面这段代码表达了基本微分关系 \(\partial_i x_j = \delta_{ij}\) (当且仅当自变量相同求导才为 1，其余全为 0) ：

This states \(\partial_i x_j = \delta_{ij}\):

apply (Var v) (Var w) | v == w = 1
apply (Var v) (Var w) = 0

线性叠加性：

Linearity:

apply (a :+: b) c = apply a c + apply b c

这正是我觉得特别有意思的地方：在配对符号 \(\langle\cdot,\cdot\rangle\) 的右侧，乘法就是常规的多项式相乘；但在左侧，乘法却对应着微分算子的复合操作！

I find this interesting: multiplication on the right of \(\langle\cdot,\cdot\rangle\) is ordinary polynomial multiplication, but on the left it is composition of differential operators:

apply (a :*: b) c = (apply a . apply b) c

apply a@(Lit _) b = a * b
apply a (b :+: c) = apply a b + apply a c

我们熟知的乘积求导法则——莱布尼茨法则 (Leibniz Rule) ：

The usual Leibniz rule:

apply v@(Var _) (b :*: c) = apply v b * c + b * apply v c

apply v@(Var _) (Lit _) = 0

现在我们在零点处进行求值。请注意，这恰好完美对应了正则表达式中“判断剩余残差表达式是否能匹配空字符串”的判定步骤：

Now we evaluate at zero. Note that this corresponds to the situation with regular expressions where you ask if the residual expression matches the empty string:

atZero :: (Num a, Eq v) => Expr v a -> a
atZero (Lit a) = a
atZero (Var _) = 0
atZero (a :+: b) = atZero a + atZero b
atZero (a :*: b) = atZero a * atZero b

最后，组装出我们的配对函数：

And finally, the pairing:

pair a b = atZero (apply a b)

颠倒乾坤：翻转求导角色

Flipping the Derivative

见证奇迹的时刻到了。在数学上有两个极其关键的定理：

Now comes the magic bit. We have two theorems:

\[ \langle p,x_i q\rangle = \langle \partial_i p,q\rangle \]

而更令人惊叹的是——考虑到多项式在配对左侧 (作为微分算子) 与右侧 (作为被求导函数) 的解释方式是如此迥然不同——它们之间竟然存在着无与伦比的完全对称性：

And, perhaps more surprisingly given how differently polynomials are interpreted on the left versus the right:

\[ \langle p,q\rangle = \langle q,p\rangle \]

让我们通过一个具体示例来亲身体验：

Let's set up an example:

main = do
  let x = Var 0
  let y = Var 1

基于上述定义，我们引入拉普拉斯算子：

With this definition:

  let lap = x * x + y * y

这里的 \(\langle \mathrm{lap}, q \rangle\) 就代表 \(q\) 在 \(x = y = 0\) 处求值的拉普拉斯算子 (Laplacian) ：

\(\langle \mathrm{lap}, q \rangle\) is the Laplacian of \(q\) evaluated at \(x = y = 0\):

  print $ pair lap ((x + y + 1) * (x - 3 * y + 2) * (x + y + 3))

高潮来了，让我们看看反转后的惊人反差：

Now comes the plot twist:

  print $ pair ((x + y + 1) * (x - 3 * y + 2) * (x + y + 3)) lap

与以往“用一个简单的微分算子去作用于极其复杂的长表达式”截然相反，现在我们是在“用一个极其复杂的微分算子去作用在一个极其简单的多项式上”！这意味着，无论输入的函数表达式 \(p\) 有多么复杂庞大，它在一步步作用于 \(q\) 的过程中所产生的任何中间结果，其代数复杂度都是被严格封顶约束的。例如在当前二维拉普拉斯的情形下，不论中间怎么求导展开，我们所能得到的全部中间结果永远只是下列基底项的线性组合 (Linear Combinations) ：

Instead of applying a simple differential operator to a complicated expression, we are applying a complicated differential operator to a simple expression. No matter how complicated an expression \(p\) we apply, the intermediate results of applying it to \(q\) are always bounded in complexity. For example, in this case we are only ever going to get linear combinations of:

\[ x^2+y^2,\quad \partial_x(x^2+y^2)=2x,\quad \partial_y(x^2+y^2)=2y,\quad \partial_x(2x)=2 \]

仅此而已！后续过程中出现的任何多项式，无一例外都只是这 4 个项的线性组合。这揭示了一个颠覆性的结论：如果我们要在二维空间中计算拉普拉斯算子，整个自动微分计算过程中我们自始至终只需要跟踪 4 个标量系数——根本不需要在内存中维护完整的黑塞矩阵 (Hessian) ！实际上，我们完全可以直接把配对右侧的多项式替换为一个四维向量 (4-vector) ，并把 apply 替换为直接在该向量表示上运行的轻量矩阵变换代码。

and that's it. Anything else that pops up is just going to be a linear combination of these. This means that if we're interested in computing the Laplacian in 2D, we only ever need to track 4 coefficients—we don't need to keep track of the full Hessian. In fact, we can replace the polynomial on the right of the pairing with a 4-vector and replace apply with code that acts directly on that representation.

至此，我们用全新的现代视角重新推导出了我多年前在博文 Computing errors with square roots of infinitesimals 中提出的拉普拉斯算子快速算法。而现在的视角更加普适统一，可以直接推广到任意常系数微分算子中！例如，双调和算子 (Biharmonic Operator) 对应于多项式 \((\sum_i x_i^2)^2\) 。当你枚举反复应用偏导算子 \(\partial_i\) 所能产生的所有可能表达式时，它们张成的空间基底维度，远远小于盲目携带直至 4 阶的完整泰勒幂级数展开所需的巨大空间！

We have just rediscovered the method for computing Laplacians I described many years ago in Computing errors with square roots of infinitesimals. Now it's more general, and we can use this for any constant differential operator. For example, the biharmonic operator corresponds to the polynomial \((\sum_i x_i^2)^2\). When you compute all of the possible expressions that can arise from applying the \(\partial_i\) operator, it forms a far smaller space than what you would get from naively carrying along the power series up to degree 4.

结语与发散思考

Final Words

在我最早提出最初的拉普拉斯快速计算方法多年之后，这一思路最终被学界重新独立发现，并在 Microsoft 开源的高性能计算库 folx 中被工程化实现为极致优化的代码。如今，它已被广泛应用于物理信息神经网络 (Physics-Informed Neural Networks, PINNs) 与变分蒙特卡洛 (Variational Monte Carlo, VMC) 等诸多尖端科学计算场景中。

After I proposed my original Laplacian method, it was eventually rediscovered and turned into well-optimized code in folx, which is used in many places such as PINNs and VMC.

读者不妨也将该视角与近期发表的研究论文 Collapsing Taylor Mode Automatic Differentiation 进行对照阅读，二者在底层代数结构上有着异曲同工之妙。

Compare also with the paper Collapsing Taylor Mode Automatic Differentiation.
